7. **前后端契约（2026-11-05 补充）**：前端为 RuoYi-Vue 风格请求层（request.js + Vuex + 路由守卫），
   登录使用账号密码 + 图形验证码，成功返回 `{ code: 200, token }`；随后携带
   `Authorization: Bearer <token>` 调用 `GET /getInfo` 获取 `user / roles / permissions`；
   业务接口统一注入鉴权头，401 触发重新登录，500 为业务异常。

## 前端对接约定

| 项 | 约定 |
| --- | --- |
| 成功码 | `200`（不是若依 Web 端的 `0`），统一响应体由 `AppResult` 输出 |
| 登录 | `POST /login`，参数 `username`、`password`、`code`、`uuid`（Web 端为 `validateCode`） |
| 验证码 | `GET /captchaImage` → `{ code, uuid, img }`，`img` 为 Base64 JPEG，前端自行拼 `data:image/jpeg;base64,` |
| 用户信息 | `GET /getInfo` → `{ code, user, roles, permissions }` |
| 鉴权头 | `Authorization: Bearer <token>`，兼容 `X-Token` 与 `?token=` |
| 令牌失效 | HTTP 200 + `{ code: 401, msg }`，前端清理本地 token 并跳登录页 |
| 退出 | `POST /logout`（小程序，清令牌） / `GET /logout`（后台，清会话后跳转） |
| 业务接口 | 暂定 `/business/**` 前缀；若前端需要兼容 RuoYi-Vue 的 `/system/**` 路径，见问题 012 |

## 实施方案

- 后端复用现有若依模块，新增单位库存采购业务和面向小程序的 JSON API。
- 小程序鉴权采用**无状态令牌 + 服务端缓存**：登录成功后签发随机令牌，身份与有效期保存在 EhCache，
  请求经 `AppAuthInterceptor` 校验后写入 `AppContext`；不复用 Web 的 Session 会话。
- AI 助手通过 Spring AI 接入大模型，RAG 检索单位知识库，Function Calling 调用受控业务工具。
- 小程序源码放在 `weixinprogram/`（微信原生或 uni-app 构建产物）。
- 数据库：服务器 `cangxiaozhu` 库（账号仅 localhost），本地开发经 SSH 隧道连接，详见 `doc/部署运行说明.md`。
- 功能范围：单位账号与角色、商品分类与商品、供应商、库存及出入库、采购与审批、收货入库、
  规则自动补货、应付账款与付款登记、预警与趋势统计、Excel 导出、操作审计。
- 审批采用预设单级审批，补货采用安全库存、季节系数、库存上限和在途采购量的规则计算。
- AI 首版范围：单位采购制度及供应商资料的文档上传、解析、切分、向量检索与引用；
  库存、采购进度、应付账款和供应商的实时问答；生成补货建议和采购草稿。
- 知识库与工具执行均在服务端绑定当前单位和用户权限，单位标识不能由模型决定。
