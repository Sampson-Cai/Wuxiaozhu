# 本地试跑说明

目标：在本机把服务跑起来，确认接口能正常返回数据。全程约 3 分钟。

## 1. 前置检查

| 项 | 检查方式 | 期望 |
| --- | --- | --- |
| JDK 17 | `java -version` | `17.x` |
| MySQL 服务 | `services.msc` 找 `MySQL`，或 `Get-Service MySQL` | Running |
| 数据库 | 已有 `cangxiaozhu_dev`（56 张表） | 不存在则按 `部署运行说明.md` 建库导入 |
| 端口 | 18080 未被占用 | 被占用就换一个端口 |

数据库与账号在 `application-druid.yml` 里通过环境变量注入，默认 `127.0.0.1:3306/cangxiaozhu_dev`、用户 `root`、空口令。口令不同时先设：

```powershell
$env:DB_PASSWORD = "你的口令"
```

## 2. 启动服务

**最省事：双击 `scripts/启动服务.bat`**，它会打开一个窗口运行 jar（已关闭验证码）。
窗口里出现 `Started RuoYiApplication` 才算启动成功，**这个窗口要一直开着**。

> 脚本 `试跑接口.ps1` 只是客户端。服务没启动时它会报“无法连接到远程服务器”，
> 表示本机没有进程在监听 18080，不是网络问题。

**命令行启动（等同双击）**

```powershell
cd D:/DSH/Qixiaozhu/cangxiaozhu
java -jar ruoyi-admin/target/ruoyi-admin.jar --server.port=18080 --shiro.user.captchaEnabled=false
```

**需要验证码时**（更接近真实环境）：去掉 `--shiro.user.captchaEnabled=false`，
登录前先 `GET /captchaImage` 拿 `uuid` 与图片，再带 `code` 提交。

启动成功的两个标志：

1. 窗口出现 `Started RuoYiApplication`；
2. `netstat -ano | findstr :18080` 能看到 `LISTENING`。

停止服务：在那个窗口按 `Ctrl + C`，或直接关窗口。

## 4. 手工调接口

### 4.1 用 Apifox / Postman

1. 新建请求 `POST http://127.0.0.1:18080/login`，Body 选 `x-www-form-urlencoded`：
   `username=admin`、`password=admin123`；
2. 返回里复制 `token`；
3. 新建请求 `GET http://127.0.0.1:18080/business/product/list?pageNum=1&pageSize=10`，
   Headers 加 `Authorization: Bearer <token>`；
4. 应返回 `{"code":200,"total":2,"rows":[...]}`。

### 4.2 用 curl（Windows 自带）

```powershell
$B = "http://127.0.0.1:18080"
$r = curl.exe -s -X POST "$B/login" -d "username=admin&password=admin123"
$token = ($r | ConvertFrom-Json).token
curl.exe -s "$B/business/product/list?pageNum=1&pageSize=10" -H "Authorization: Bearer $token"
```

> Git Bash 里直接用 `curl` 即可；注意中文参数要写成 UTF-8 文件再用 `--data-binary @file`，否则 Windows 控制台会按 GBK 发送导致 `JSON parse error`。

### 4.3 用 PowerShell 原生（注意解码）

`Invoke-RestMethod` 在 PowerShell 5.1 下会把 UTF-8 的 JSON 当 Latin-1 解，中文变乱码。用下面写法可避免：

```powershell
$resp = Invoke-WebRequest "http://127.0.0.1:18080/business/product/list" -Headers @{ Authorization = "Bearer $token" }
[Text.Encoding]::UTF8.GetString($resp.RawContentStream.ToArray()) | ConvertFrom-Json
```

`scripts\试跑接口.ps1` 里已经封装好了这个解码逻辑。

## 5. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动报 `Port 18080 was already in use` | 端口被占 | 换端口 `--server.port=18081`，或结束占用进程 |
| 启动报 `Access denied for user 'root'` | 数据库口令不对 | 设 `$env:DB_PASSWORD`，或确认 MySQL 允许 root 本地登录 |
| 启动报 `Unknown column 'xxx'` | 库表结构旧了 | 重新执行 `sql/cangxiaozhu_schema.sql` |
| 调接口返回 `{"code":401}` | 没带 token 或 token 过期 | 重新登录，Header 用 `Authorization: Bearer <token>` |
| 返回 `{"code":403}` | 当前账号没有该权限点 | 用 admin，或在角色里分配 `business:xxx` |
| 中文显示乱码 | 客户端按 Latin-1 解码 | 用 Apifox/浏览器开发者工具，或按 4.3 的写法解码 |
| 登录提示“验证码错误” | 验证码开启且没带 code/uuid | 启动时加 `--shiro.user.captchaEnabled=false` |

## 6. 验证“数据能传出去”的判定标准

满足以下任意两条即可认为链路通：

1. `/login` 返回 `code=200` 且有 `token`；
2. `/getInfo` 返回 `user/roles/permissions`；
3. `/business/product/list` 返回 `rows` 且 `total > 0`；
4. 不带 token 访问返回 `code=401`。
