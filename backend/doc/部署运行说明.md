# 部署运行说明

> 环境：JDK 17 / Maven 3.9+ / MySQL 8.0+ / Spring Boot 4.1.0（若依 4.8.3）
> 当前部署方式：**本机运行**，数据库为本机 MySQL（不使用云服务器）。

## 1. 数据库

### 1.1 库与账号

| 项 | 值 |
| --- | --- |
| 库名 | `cangxiaozhu_dev`（utf8mb4 / utf8mb4_general_ci） |
| 账号 | 本机 `root`（开发环境），口令通过 `DB_PASSWORD` 注入 |
| 表数量 | 56 张（若依基础表 + 业务表 + Quartz） |
| 权限数据 | `sql/cangxiaozhu_menu.sql`：10 个权限点 + 库管/采购/审批三个角色 |

口令不写入仓库，`application-druid.yml` 使用 `${DB_PASSWORD:}` 占位；本机 root 为空口令时可不设置。

### 1.2 初始化脚本

```bash
# 建库
mysql -uroot -e "create database if not exists cangxiaozhu_dev default character set utf8mb4 collate utf8mb4_general_ci;"

# 导入（字符集参数不能省，否则中文报 Data too long for column 'dept_name'）
mysql -uroot --default-character-set=utf8mb4 cangxiaozhu_dev < sql/ry_20260319.sql
mysql -uroot --default-character-set=utf8mb4 cangxiaozhu_dev < sql/quartz.sql
mysql -uroot --default-character-set=utf8mb4 cangxiaozhu_dev < sql/cangxiaozhu_schema.sql
mysql -uroot --default-character-set=utf8mb4 cangxiaozhu_dev < sql/cangxiaozhu_menu.sql
```

校验：

```sql
select count(*) from information_schema.tables where table_schema = 'cangxiaozhu_dev';  -- 56
select user_id, login_name, enterprise_id from sys_user limit 3;                         -- admin 归属单位 1
select id, name from t_enterprise;                                                       -- 演示单位
```

初始账号 `admin / admin123`，首次登录后立即修改。

| `DB_USER` | root | 账号 |

## 3. 启动

```bash
mvn -B -DskipTests clean package

# Windows PowerShell
java -jar ruoyi-admin/target/ruoyi-admin.jar --server.port=18080

# Git Bash（有口令时）
DB_PASSWORD='***' java -jar ruoyi-admin/target/ruoyi-admin.jar --server.port=18080
```

首次联调可关闭验证码，便于脚本调用：

```bash
java -jar ruoyi-admin/target/ruoyi-admin.jar --server.port=18080 --shiro.user.captchaEnabled=false
```

## 4. 接口冒烟

```bash
TOKEN=$(curl -s -X POST http://127.0.0.1:18080/login \
  -d "username=admin&password=admin123" | sed 's/.*"token":"\([^"]*\)".*/\1/')

curl http://127.0.0.1:18080/getInfo -H "Authorization: Bearer $TOKEN"
curl http://127.0.0.1:18080/business/enterprise -H "Authorization: Bearer $TOKEN"
curl http://127.0.0.1:18080/business/product/list -H "Authorization: Bearer $TOKEN"
```

| 用例 | 期望 |
| --- | --- |
| `POST /login` | `{"code":200,"token":"..."}` |
| `GET /getInfo`（带 token） | `{"code":200,"user":{...},"roles":[...],"permissions":[...]}` |
| `GET /getInfo`（无 token） | `{"code":401,...}` |
| `POST /logout` 后复用 token | `{"code":401,...}` |
| 开启验证码时错误验证码 | `{"code":500,"msg":"验证码错误"}` |

业务接口明细见 [接口说明](接口说明.md)。

## 5. 小程序联调注意

- 请求头：`Authorization: Bearer <token>`；文件下载无法设置请求头时可带 `?token=`。
- 写接口：必须再带 `X-Request-Id`（UUID），否则返回 500，重复提交返回 409。
- 合法域名：小程序后台需配置 request / uploadFile / downloadFile 域名，且必须为 HTTPS。
- 本地联调：开发者工具勾选“不校验合法域名”，或将 `baseUrl` 指向内网穿透地址。
- 令牌有效期 7 天，临期自动续期；服务端删除令牌即失效（存于 EhCache，重启后需重新登录）。

## 6. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `1045 Access denied` | 账号或口令不符 | 检查 `DB_USER` / `DB_PASSWORD`，确认库账号权限 |
| 导入时报 `Data too long for column 'dept_name'` | 客户端字符集不是 utf8mb4 | 加 `--default-character-set=utf8mb4` |
| 接口报 `Unknown column 'xxx_id'` | 库表结构与代码不一致 | 重新执行 `sql/cangxiaozhu_schema.sql` |
| 启动后登录返回 500 | 库表未导入或 `sys_user.enterprise_id` 缺失 | 重新执行建库脚本 |
| 写接口报 `JSON parse error: Invalid UTF-8` | 命令行按 GBK 发送中文 | 请求体写入 UTF-8 文件后用 `--data-binary @file` |
| 登录提示验证码错误 | 验证码缓存 2 分钟且一次性 | 重新获取 `/captchaImage` |

### 更新发布（云端构建）

本项目为**纯云端构建**：本地只负责 `git push`，编译与发布全部在服务器完成。

```bash
# 1. 本地：提交并推送
git add -A && git commit -m "feat: xxx" && git push origin main

# 2. 服务器：一条命令拉取 + 编译 + 替换 + 重启 + 健康检查
ssh -i ~/Documents/Main/Ubuntu.pem ubuntu@152.136.137.81 /opt/qixiaozhu/deploy.sh
```

`deploy.sh` 的动作：

| 步骤 | 说明 |
| --- | --- |
| 1 | `git fetch --depth 1 origin main` + `git reset --hard origin/main`（代码目录 `/opt/qixiaozhu/src`） |
| 2 | `cd src/backend && mvn -B -DskipTests package`（Maven 3.8.7 + JDK 17，镜像走阿里云） |
| 3 | 停 `qixiaozhu` 服务 |
| 4 | 旧包备份为 `ruoyi-admin.jar.bak`，替换新包 |
| 5 | 启动并轮询 `/captchaImage` 直到返回 200（最多 120s） |

- 日志：`/opt/qixiaozhu/logs/deploy.log`
- 跳过拉取、只重编译当前工作区：`/opt/qixiaozhu/deploy.sh --no-pull`
- 回滚：`cp /opt/qixiaozhu/app/ruoyi-admin.jar.bak /opt/qixiaozhu/app/ruoyi-admin.jar && sudo systemctl restart qixiaozhu`
- 服务器已加 2G swap（`/swapfile`），避免 3.7G 内存下编译被 OOM 杀掉

> 小程序仍需本地构建（`npm run build:mp-weixin`）后用微信开发者工具上传，服务器不参与小程序打包。

### 反向代理与 HTTPS（宝塔 nginx）

云安全组只放行 80/443，`18080` 公网不可达（ufw 也已关闭 18080、3306），因此用 nginx 承接 443 再反代到本机 18080。

```bash
# 站点配置（宝塔 vhost 目录，nginx.conf 已 include）
/www/server/panel/vhost/nginx/demo7.ztcoding.com.conf
# 证书（Let's Encrypt，webroot 续期，deploy hook 自动 reload nginx）
sudo certbot renew --dry-run --cert-name demo7.ztcoding.com
```

- 系统 apt 版 nginx 已卸载（备份 `/root/nginx-apt-backup-*.tar.gz`），现在只有一个 nginx：宝塔的 `/www/server/nginx/sbin/nginx`，systemd 单元 `/etc/systemd/system/nginx.service` 已 enabled。
- 80 端口在 vhost 里 301 到 https，并保留 `/.well-known/acme-challenge/` → `/var/www/certbot` 供证书续期。
- 续期方式从 certbot 的 nginx 插件改为 **webroot**（插件只认 apt nginx，迁移后会失效），续期后由 `/etc/letsencrypt/renewal-hooks/deploy/reload-nginx.sh` 重载服务。
- `/business/ai/chat/stream` 单独一段 location：`proxy_buffering off`、`gzip off`、300s 超时，保证 SSE 逐段下发。
- 反向代理超时 180s，因为 AI 问答单次要 4~15 秒。
- 后端不再直接对外，systemd 单元里已固定 `--server.address=127.0.0.1`。

> 注意：该站点是手写的 vhost 配置文件，宝塔面板「网站」列表里不会显示；面板里能管理的是 nginx 本身（软件商店 → Nginx 显示 1.24 运行中）与 SSL/配置。改站点请直接编辑上面那个 conf，然后 `sudo systemctl reload nginx`。

### 安全加固

| 项 | 现状 |
| --- | --- |
| 登录验证码 | **已开启**（`shiro.user.captchaEnabled: true`，启动参数不再覆盖）。小程序登录页按 `/captchaImage` 返回的 `captchaEnabled` 自动渲染输入框，验证码按 `uuid` 存 EhCache 2 分钟、一次性失效 |
| 公网放行端口 | 仅 `22`、`80`、`443`、`16988`（面板）。已关闭 `3306`、`18080`、`888`、`8888`、`20`、`21`、`39000:40000` |
| 后端监听 | `127.0.0.1:18080`，公网不可达，只能经 nginx 443 进入 |
| 数据库 | MySQL 只监听本机，`wxz@localhost`，公网不可连 |
| 面板 API | 已启用密钥 + IP 白名单双重校验，非白名单 IP 直接拒绝 |
| 面板访问 | 安全入口 `d4ea5c68` + 面板 SSL；非浏览器 UA 会被拦成 404（防扫描） |

验证码链路的自检方法（不需要真账号）：

```bash
# 1. 取图，读算术题答案
curl -s https://demo7.ztcoding.com/captchaImage | head -c 120
# 2. 不带 code / code 错误 → 均返回“验证码错误”
# 3. 带正确 code + 错误密码 → 返回“用户不存在/密码错误”（说明验证码已放行）
# 4. 同一 uuid 重复提交 → 返回“验证码错误”（一次性失效）
```
